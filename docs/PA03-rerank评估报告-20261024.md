## 3. 回归批次（11 题，全量 CE ml512 vs 基线）

- top1 翻转 3/11，**三次全部是改善**：每天睡几小时（期望文档 3→1）、成人腹泻
  补水（期望文档未命中→1）、腹痛胸闷咳嗽选科（3→1）。**零期望文档丢失。**
- ml512 全量 CE 的排序质量是可靠的；问题只在耗时。

## 4. 两个否决/警示数据

1. **候选集截断不可行**：k=20 时"成人腹泻补水"丢失期望文档蒙脱石散——该文档
   向量排名在 20 开外但 CE 能救回（k50 全量 CE 下 rank 1）。先截候选再 rerank
   会把 CE 的价值掐掉。
2. **ml192 截断是压线方案且有质量代价**：唯一能进 5s 预算的档位，但复测耗时
   4.7~5.5s 波动，且回归批次出现 4 次 top1 翻转、个别期望文档名次后移
   （腹泻补水 1→9、腹痛选科 1→6）。虽 11/11 期望文档仍全在 top-10 内（零丢失），
   但排序劣化是真实代价，且 5.5s 已超出 TOOL_BUDGET(5s)。

## 5. 结论

1. **rerank 对这类个案有效，且对常规题非回归**（§3）；瓶颈是纯 CPU 推理耗时，
   ml512 可靠档 13.9s 无预算可行性，ml192 压线档以排序质量换时间。
2. **query 侧有 headroom**（C 手段零成本到 rank 2），但手工同义改写不可系统化；
   系统化形态 = LLM query rewrite，代价是每次知识问答 +1 次 LLM 调用（classify
   实测 4s）与改写语义丢失风险（需沿用 N02「保留实体」纪律）。
3. **任何昂贵手段都不该放在主检索路径上**。现有架构已有 designated slot：
   N09 回边（证据不足时的一次受控重试，当前实现为 k+2 扩大候选、近无效）。
   把回边从「k+2」升级为「k=50 候选 + CE rerank（ml512 可靠档）」，只在首轮
   判定 insufficient 时付出 13.9s——此时本就要么拒答要么空转，rerank 是这笔
   预算的最优用途；常规路径（81.9% 的 completed 题）零新增延迟。

## 6. 建议方案与门槛（未实施，待确认）

**建议（选项 A）**：改造 N09 回边为「扩大候选 + CE rerank」：
- 子 Agent 内新增 rerank 阶段：首轮 k=10 判定 insufficient → 重试时 k=50 →
  bge-reranker-base 全量（ml512，不保序截断）→ top-10 重判，回边仍最多 1 次；
- 重试环节检索预算 5s → 15s（仅重试路径），复核最坏路径 37.4s + 13.9s ≈ 51s
  与 REQUEST_DEADLINE(45s) 的冲突——需相应上调 deadline 至 ~55s 或压缩生成预算，
  **这是需要拍板的取舍**；
- reranker 客户端单例化（惰性 + 锁，同 embedding 先例），启动预热可选；
- 验收门槛：① PA-03 链路级转 completed（真实 LLM）；② 72 题 run5 覆盖充分率
  ≥81.9% 不回落；③ 门禁 G-3 复测通过（新最坏路径实测 ≤ deadline）；
  ④ 单测新增（rerank 守卫、k 上限、超时归一、模型缺失降级）。

**备选（选项 B）**：维持现状，PA-03 记为已知边际个案——rerank 收益面目前仅
1 题（回归批次的改善属于锦上添花而非修缺陷），13.9s 的架构代价是否值得，
取决于 PA-03 类个案的攒批速度。

**否决**：主路径 rerank（所有知识问答 +5~14s）；k<50 候选截断；ml192 压线档。
