# 上下文工程 V1 接口契约

日期：2026-10-27。本文是上下文工程向提示词工程提供的最小输入契约，不定义提示词策略。

## 1. 数据流与边界

- 原始消息仍由 `conversations.messages` append-only 保存；`session.py` 仍负责近期窗口与锁。
- 只有需要多轮补充/恢复的任务才写入 `agent_tasks`；普通问答不创建持久化任务。
- 用户明确提供的身高、体重可写入 `user_facts`，必须关联同用户、同会话的来源消息。
- Chroma 只保存共享外部知识。用户事实不得写入 Chroma，也不得与检索证据混用。
- 知识 Worker 仍只收到补全后的独立问题与 deadline，不接收个人事实或原始历史。

## 2. ContextPackage

`build_context(...) -> ContextPackage` 的最小字段：

| 字段 | 含义 |
| --- | --- |
| `current_question` | 本轮用户原始/当前问题，独立于历史，不由摘要替代 |
| `task` | 当前唯一待续任务；多候选未消歧时为 `None` |
| `recent_history` | 经筛选的原始消息，保留 role、内容、message_id、turn、时间 |
| `relevant_facts` | 用户明确提供的事实，含来源、单位、时间、status 与 freshness |
| `retrieval_evidence` | 外部检索片段，含文档、页码与内容 |
| `missing_information` | 当前任务仍缺少的输入；不是模型技术错误 |
| `conflicts` | 同类型有效事实的冲突值及 fact_id，不在组装时静默覆盖 |
| `source_refs` | 本轮上下文可追溯来源标识 |
| `token_estimate` / `token_budget` | 调用前的估算值与预算；估算不是模型 tokenizer 的精确值 |
| `context_status` | 复用现有 `ContextStatus`，表达历史缺失/降级 |
| `assembly_status` | `ok`、`budget_exceeded` 或 `invalid_input` |
| `omitted_history_turns` | 因低相关或预算未纳入的完整轮次数，不代表删除数据库历史 |
| `candidate_task_count` | 当前待续候选数；大于 1 时不得擅自关联 |

`freshness=current_user_provided` 仅用于本轮明确输入；从 SQLite 读取的旧事实标为
`historical_unconfirmed`，即使仍为 active 也不得自动当成当前测量值。

V1 不生成历史摘要，提示词工程不得依赖 `summary`、模型推断事实或跨会话长期记忆字段。

## 3. 任务状态

`TaskRecord.status` 使用 `waiting_for_input / ready / running / completed / failed / cancelled`。
`missing_inputs` 由 `required_inputs - provided_inputs` 得出。只有原始回答与任务结果已落库后，
运行中的任务才能持久化为 `completed`。补充输入只允许关联同用户、同会话的唯一兼容任务；
多候选或冲突必须澄清，不按“两个数字”猜任务。

## 4. 失败与预算语义

- 当前问题、任务必需参数、冲突和证据属于必需上下文；预算不足时返回
  `assembly_status=budget_exceeded`，不得静默删除后照常调用。
- 历史按完整轮次筛选，单条消息不改写；否定、时间、单位和限定语因此不会因摘要而丢失。
- 旧事实保留其时间与来源，但不自动填充新任务参数；执行任务只使用当前补充或该待续任务
  已确认的参数。
- 上下文组装失败不是医学结论、证据不足或用户意图未知。

## 5. 非职责

本模块不决定系统提示词、医学回答风格、分类 Prompt、证据判定 Prompt 或提示词版本。
提示词工程只消费上述显式字段，不应从用户事实生成公共知识，也不得绕过现有认证与授权。
