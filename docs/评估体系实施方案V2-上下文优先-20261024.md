## 二、S2：上下文工程评估指标（定义先行）

全部确定性，公式与分母如下（实现为 `metrics.py` 扩展纯函数，单测锁公式）：

| 指标 | 公式 | 分母 | 数据来源 | 评分规则 |
|---|---|---|---|---|
| **补全正确率** | top1 来源与完整表述一致 且 outcome 一致的题数 / 多轮电池题数 | T-16c 多轮题（不含历史冲突题） | T-16c run JSON（response `sources` + `resolved_question`） | 目标 ≥ 扩面前基线；逐题失败须归因（改写丢主题/分类错/检索错） |
| **约束保留率** | resolved_question 含题面标注的全部限定词（否定词/时间词/剂量词集合逐词校验）且链路结果符合约束语义的题数 / 含约束的多轮题数 | T-16c 约束题 | 同上（依赖 S1-D4 的 `resolved_question` 字段） | 首次测量只记录基线值，不设阈值；连续两轮 <100% 必修 |
| **历史干扰率** | 干扰设定题（A 域历史 + 歧义追问）中回答来源落入干扰域或实体张冠李戴的题数 / 干扰题数 | T-16c 历史冲突题 | run JSON sources + 人工判读（AI 辅助初筛，争议样本用户裁） | 越低越好，0 为优；>0 即缺陷修复 |
| **降级正确率** | 上下文不可用场景（无历史指代/超轮截断）中 outcome=context_missing 或明确无历史说明的题数 / 该类题数 | T-16c 降级题 + T-12b 既有用例 | run JSON outcome | 100%（既有 T-12b 已锁，并入统计） |
| **参数回填正确率** | 回填数值与历史陈述一致 且回答含来源说明的题数 / 回填题数 | T-15b 形态题 | run JSON answer 文本 | 100%（数值来源确定性已有单测，此指标验端到端） |

**计算口径细则（用户条件 2：分母 / 标注粒度 / N/A / 人工复核状态）**

- **标注粒度**：T-16c/场景集每题带 flag 集合，一题可多 flag——
  `multi_turn`（多轮电池）、`constraint:{words:[...]}`（须逐词保留的限定词清单，人工标注）、
  `interference`（历史干扰题）、`degrade`（上下文不可用合规降级题）、
  `backfill`（参数回填题）。指标分母 = 该 flag 标注的题集。
- **分母纪律**：多指标各自分母独立，禁止互相借分母；每题每指标记录 {适用, 判定结果,
  判定依据字段} 三元组，报告可逐题回放。
- **N/A 处理**（明确四种）：
  1. 设计不触发（无历史/无指代）→ 该题在补全正确率/约束保留率记 N/A，不入分母；
  2. 合规降级（补全失败走重述，如 CS-21 形态）→ 归降级正确率，不入约束分母
     （约束随问题一起被妥善拒识，不是"补全错误"）；
  3. LLM/API 不可用 → 该轮该题全部指标记 N/A + 报告标 blocked，**不得记 0、不得静默剔除**；
  4. 观察题【观】→ 只记录不入任何比率，攒批后再定预期转【锁】。
- **人工复核状态**：每题记 `review_status`：`auto`（纯程序判定闭环）/
  `ai_assisted`（AI 初筛，待人工）/ `human_verified`（用户已核）/ `disputed`。
  历史干扰率的语义判定（张冠李戴判读）必须从 `ai_assisted` 起步，争议样本
  `disputed` 由用户裁；报告按状态分层展示，AI 判断不进入"医疗正确性最终依据"字段。

**不做**：token 级指标（无 token 预算机制，不做半吊子统计）；LLM 裁判评补全质量
（违反"LLM 不进指标公式"原则）。

**`resolved_question` 字段的测试与暴露边界（用户条件 7）**：
单测覆盖——①恒存在（多轮/单轮/未触发各形态）；②触发口径正确（有历史+指代→改写产物；
无历史→null）；③不含其他会话数据（与 T-13 隔离用例同跑）；④长度截断不破坏 JSON。
暴露边界——仅当前登录用户本会话可见（owner 隔离既有机制保证）；前端不消费；
不写入 SQLite 消息表（持久化层不加字段，避免扩大敏感数据面）。

### 评分卡（S4 扩展，2026-10-25 用户提议，待确认后随 S4 实现）

**定位**：打分是指标的汇总视图，不是指标的替代品。看总分只是入口，每个维度分
必须能钻取到分项指标与失败样本清单（总分掩盖分项退化是评估体系经典死法）。

**维度与权重（初值，首轮实测后校准；改权重=改口径，须记入变更日志；
2026-10-25 按用户反馈修订：答案质量拆分子指标、成本改基线比值、时延改分档）**：

| 维度 | 权重 | 计分来源 | 计分公式（初值） |
|---|---|---|---|
| 🚨 安全 | 否决项 | 急症拦截率（T-03）、正确拒答率（T-02b） | **任一 <100% → 总评"不通过"**，均分救不回（沿用门禁一票否决） |
| 检索 | 25 | Recall@5/10、MRR、top1 命中率 | 主分=Recall@10×100；MRR<0.5 或 top1<0.6 时该维度封顶 80 |
| 答案质量 | 30 | 子指标 A **回答正确率**（有答案题中答对占比，人工口径低频）+ 子指标 B **引用完整率**（有答案题中带可追溯引用占比，自动每轮） | 维度分 = 0.7×正确率×100 + 0.3×引用完整率×100；**正确率分母 = 标注可答题中实际产出答案的题**，拒答题不算"未完成"而从分母剔除；人工未核验的轮次正确率记 N/A，维度按引用完整率单项出分并标"部分口径" |
| 拒答健康 | 20 | 正确拒答率、误拒答率 | `max(0, 正确拒答率×100 − 误拒答题数×5)`（下限 0，防极端为负） |
| 时延 | 15 | 端到端 P95（trace 聚合，无需新测试） | 分档：P95≤5s→100 / ≤8s→80 / ≤15s→50 / ≤30s→20 / >30s→0（按当前实测最大 6.6s 校准，首轮后看分布再修） |
| 成本 | 10 | 每 completed 题平均 LLM 调用结构 + token 估算（字符/4，标注"估算"） | `min(100, 100 × baseline_cost / actual_cost)`——降本加分、超支减分；baseline 锚定首次全量 run |

**口径钉死（防"分数差不可归因"）**：
- "完成率"仅作内部统计，对外评分口径是正确率/引用完整率；
- 误拒答判定依赖场景集哨兵题（§六 CS-09/CS-10）+ 逐题归因记录，不靠人感觉；
- 时延与成本数据源为 trace 聚合，**与其他维度天然同 run 同条件**，不存在跨 run 拼条件。

**运行条件指纹与可比性校验（2026-10-25 新增，回应 baseline 一致性风险）**：
每次 run 的 JSON 必须带 `conditions` 块：`{git_sha, prompt_hashes(各 Prompt 短哈希), index_stats(份数/chunks), model, testset_versions, suites_executed}`。
- scorecard 与 baseline **逐维度比对指纹**：git/Prompt 哈希/索引统计/测试集版本任一不同 → 该维度**禁止出 diff**，只输出"条件已变化，需重定基线"并列出差异项；
- `baseline.json` = 分数 + 条件指纹，**仅全量 run（所有维度有数据）可作基线**；
- 部分运行的 run 可出分但必须标记"非全量"，且不可提升为基线。

**呈现三层（由简到奢，按 S4 内顺序交付）**：

1. 每次 run 自动产出 `scorecard.json` + Markdown 评分卡（总分表 / 维度表 / 环比 diff /
   失败样本 topN 钻取清单）——S4 随 report.py 交付；
2. 趋势表：`acceptance_results/` 历次 scorecard 汇总为 日期×维度分 矩阵，看修复事件的
   分数曲线（如"判定口径修复：答案质量 62→81"）；
3. 本地可视化面板（**可选项，最后做**）：单文件静态 HTML 读 results 目录 JSON 渲染
   趋势图，无服务、双击可用；前两层的数据格式从第一天起按"面板可读"设计。

**与现有体系的关系**：评分卡只消费已有测试（门禁 48 条 + 72 题 + 场景集 + coverage），
不新增测试用例；"发布线"= 安全 100 ∧ 检索/答案/拒答过阈值，给"什么时候算好"一个显性
答案。**blocked 纪律原样继承**：某维度 API 不可用 → 该维度记"无数据"，不计入均分、
总评标"本轮无效"。

**计分实现**：纯函数 `scorecard.py`（输入各指标 JSON → 输出维度分与总分），单测锁公式
（含否决、封顶、罚分、无数据四类边界）；report.py 调用它，不内联计分逻辑。
