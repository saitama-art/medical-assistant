## B. 3 分钟技术面试项目介绍

> 口语版，约 700 字，按"问题 → 架构 → 难点 → 取舍 → 结果"讲述。

我做的是一个医疗健康智能助手，业务上解决一个典型矛盾：用户希望像聊天一样问健康问题，但医疗场景要求每条结论都有依据、宁可拒答不能编造，急症还必须第一时间拦住。所以我没有做成"大模型 + Prompt 直接答"，而是做了 RAG 加可控 Agent 的架构——LLM 只负责"理解用户说了什么"和"把证据组织成人话"，其他全部交给确定性代码。

架构上是一个主 Agent 带一个知识子 Agent。主 Agent 是一条 13 节点的显式流程：进来先做两轮纯规则的急症检查——在查知识库之前就把"胸痛、喘不上气"这类输入直接拦截掉，零检索零生成，这条路径是医疗产品的安全底线，规则还有强弱分级和否定处理，比如"我没有胸痛"不会被误拦。然后寒暄走规则短路，意图识别用 LLM 做一次结构化分类，路由是完全确定性的映射表——不存在"模型自己决定下一步干什么"的循环，工具调用有白名单、Schema 校验、最大轮数。知识类问题委派给子 Agent：子 Agent 只拿到问题本身和预算，不继承会话历史，内部做"检索 → 证据判定 → 生成"，把结构化的结果交还父 Agent 统一组装回答和来源。

几个我认为最有讲头的设计：第一是证据判定。我们实测发现"检索到相关文档"和"文档能回答问题"完全是两回事——问血压正常范围会命中降压药说明书。所以判据分三段：模型判 answerable、并且必须给出逐字引用、程序再做字符串逐字校验，引文不在原文里直接拒答。我们还专门做了距离阈值的校准实验，实测发现两类问题的距离分布完全重叠，就数据驱动地决定不用距离粗筛，而不是拍一个 0.85。第二是多轮上下文，追问"它的副作用呢"会用 LLM 补全成指代明确的独立问题，而且要求保留实体不许泛化；历史上算过的 BMI，追问"我的BMI"会从会话历史补参数再算，但数字永远由确定性函数产出，模型只负责补问法。第三是工程化：整条链路每个环节有独立的时间预算，超时用 httpx 原生实现而不是线程池——后者在 `with` 退出时会等任务结束，超时是假的；embedding 客户端单例化把检索从十几秒降到 14 毫秒。

结果方面：全量验收门禁 48 条用例真实 LLM 全过，后端两百多个单测全绿。我们建了一个 72 道题的覆盖测试集，通过逐题归因驱动了三轮改进——把覆盖充分率从 50% 做到 81.9%，安全拦截 5 题零失误，剩下 7 道拒答题全部归因到资料内容层，系统侧问题清零。过程中修掉的真实线上 badcase 包括卒中征象漏拦、隐性回指丢主题、判定层口径过严误拒，每一个都有根因记录和回归测试。

## C. 1 分钟精简版

我做的是一个医疗健康 RAG + Agent 助手，核心思路是让 LLM 只做语义理解，把安全、路由、证据判定全部做成确定性代码。架构是一个主 Agent 编排 13 个节点的显式流程，前面是纯规则的急症拦截——高危输入零检索零生成直接给就医指引；中间是 LLM 意图分类和确定性路由；知识问题委派给子 Agent，内部做检索、三段式证据判定——模型必须给出逐字引用、程序校验引文真实性，证据不足一律拒答不生成。多轮追问由 LLM 补全指代，健康计算走确定性工具，模型不碰数字。工程上有逐环节时间预算和门禁测试。验证上有一套 72 题固定测试集，覆盖充分率从 50% 提到 81.9%，48 条验收门禁真实 LLM 全过，两百多个单测全绿。最近还补了登录和用户数据隔离，scrypt 哈希、服务端 Session、CSRF 和限流都有测试覆盖。

## D. 架构流程说明（一次请求的完整旅程）

以 `POST /agent/chat` 收到 `{session_id, question}` 为例：

1. **N00 请求受理**：生成 request_id，按 session_id 取会话历史（进程内 5 轮窗口，会话级锁 2s 超时则降级为无历史模式并告知）；写入 45 秒全局 deadline。
2. **N01 急症检查（第一趟，原文）**：纯规则扫描 9 组急症词，做主语/语境/否定/元问题分级。命中 STRONG → 直接组装固定紧急文案（"立即前往急诊/拨打120"）+ 免责声明返回，**不触发任何检索与生成**。规则自身异常 → 保守就医提示。
3. **N02 上下文补全（条件触发）**：有历史且本轮含指代词（"它/这个药"）或隐性追问开头（"那什么情况…"）时，调 LLM 把问题改写为自包含问题，提示词强制"保留实体、不得泛化"；失败或预算不足则标记 missing，**不猜指代**。
4. **N03 急症检查（第二趟，补全后）**：再扫一次规则，捕获跨轮指代引入的急症（上轮"胸口疼"、本轮"挂哪个科"），取两趟更强者。
5. **N04a 计算规则短路**：规则解析器识别 BMI/标准体重/单位换算意图。参数齐全 → 确定性函数计算（0 LLM 0 检索），结果过范围校验；缺参但历史非空 → 用 LLM 从历史补问法后回流确定性计算，并告知"参数取自此前对话"；组合问法（"BMI 是多少？有什么危害？"）先算后把剩余部分交知识子 Agent。
6. **N04 意图识别**：寒暄整句规则短路（0 LLM）；否则 LLM 输出结构化 JSON（5 类 + confidence），非法输出或置信 <0.6 → unclassifiable。
7. **N05 条件路由**：查确定性路由表——紧急→固定文案；上下文缺失且含指代→要求重述；闲聊→固定话术；无法处理→固定话术；triage→通用就医指引固定文案（工具本阶段未注册）；knowledge→进入第 8 步。
8. **委派知识子 Agent（N06–N10）**：父 Agent 检查启动预算（不足 8s 不启动，防假动作）→ 子 Agent 在隔离上下文里执行：
   - N06/07：工具层做 Schema 校验（k 必须 1~10、问题 ≤500 字），拦截重复调用与超轮数，然后执行向量检索（k=10），异常归一为 RETRIEVAL_ERROR、空结果归一为 EMPTY_RESULT；
   - N08：三段证据判定——第 3 段 LLM 判"片段是否包含回答所问的依据"并要求逐字引用（8s 预算）→ 第 2 段程序做逐字字符串校验，不命中有界重试 1 次（只修格式不翻结论）→ 任一段失败即 insufficient，判定异常一律 insufficient；
   - N09 回边守卫：证据不足且四个条件同时满足才允许重试一次（k+2 扩大候选）；triage 不证据判定直接结束；
   - N10：以片段为唯一事实来源生成回答（12s 预算，复用医疗 Prompt，temperature=0）。
9. **N11 回答组装（父 Agent）**：固定顺序拼接——风险提示（弱紧急信号）→ 无历史说明 → 正文 → 来源（文档名+页码，按文档聚合、每文档最多 3 页、最多 3 个文档）→ 免责声明。来源全部取自检索元数据，模型不参与。
10. **N12 追踪收尾**：落 13 种终止原因之一，全程 trace（节点、决策、耗时、剩余预算）供排查；会话写回（user/assistant 各一条）；全量历史双写 SQLite（登录版）。trace 不落用户原文、不含密钥。

## E. 10 个最可能的技术追问及回答要点

**1. 为什么不用 LangGraph / 不让 LLM 自主决定工具调用？**
我们的流程是 13 节点、1 条回边，一维顺序推进，框架换不来表达能力只增加概念负担。LLM 自主循环更不能用：本项目最不可接受的失败是"模型自己判断检索够了"绕过证据闸门——证据是否充分必须由确定性判定。路由、轮数、预算是编译期可见的常量，不存在"模型不肯结束"的失控形态。已写下迁移边界：出现多条回边、需要状态持久化、需要跨进程拆分时重新评估。

**2. "检索到相关文档但没回答问题"怎么拦？（T-02b）**
实测案例：问"血压正常范围"，top1 命中氨氯地平说明书但只有量效数据。只比距离阈值会把它放行。我们的判据：LLM 判 answerable（口径是"相关性+可支撑性"，不要求资料能单独写完整答案——这个口径表述本身是一次实测修正，原来口径过严导致把直接相关词条误拒）+ 必须给出逐字 supporting_quote + 程序字符串校验。要诚实说明保证限度：第 2 段能形式化证明"引用文字真实存在"，但"引用回答了问题"是模型判断，不是形式化保证，所以配合抽样人工核验（FR-01）。

**3. 距离阈值为什么不用？（数据驱动决策案例）**
不能拍 0.85：盘点用 langchain_community.Chroma，生产用 langchain_chroma.Chroma，距离刻度不同（实测生产路径是平方 L2）。写了校准脚本实测两类分布：相关 0.244~0.378、无关 0.286~0.689——无关类最小值落在相关类范围内（问药价也会命中正确的说明书，只是文档里没答案），任何阈值都会双向误判。结论：维持 None 禁用，判定交给第 3 段 LLM + 第 2 段逐字校验，并用 T-02b 证明其可靠。未校准时第 1 段禁用是代码层保证，不是口头约定。

**4. 急症规则怎么设计？漏拦了怎么办？**
纯规则、无 LLM、无 IO，可复现可审计——因为安全底线不能依赖一个会故障的组件。分强弱两级：命中急症词后看主语/语境词升级 STRONG，元问题标记（"说明书里写了胸痛吗"）降级 WEAK 只加风险提示，裸症状词维持 WEAK。否定处理按词逐个判定且在分句内回溯，"我没有胸痛但现在突然喘不上气"仍按 STRONG（保守优先）。真实漏拦案例：「我的一侧手脚无力，口角歪斜」——前一分句的"无"跨标点吃掉了后一分句的症状（否定窗口越界），加上词表没有"一侧手脚无力"这个插入式变体，两个缺陷叠加整条漏拦。修法：否定窗口在分句标点处截断 + 补偏侧变体词表，19 条单测锁定，端到端复测 emergency_handled。

**5. 多轮追问/指代消解怎么做？改写会不会丢语义？**
条件触发：有历史、未截断、含显式指代词或句首"那什么/那该"类隐性追问。LLM 改写提示词明确"保留实体"规则——不得把具体问题泛化成通用问题（反例："腹泻要去医院的情况"不得泛化成"什么情况要去医院"）。隐性回指还覆盖计算参数：「我的BMI」零代词，靠"计算意图明确+参数缺失+历史非空"触发，LLM 只从历史提取参数补成自包含问题，再交回规则解析器，数字仍由确定性函数产出——模型不心算。补不出来一律降级为追问文案，不猜。时间范围类约束没有专门机制（如实说明是已知边界）。历史超 5 轮截断置 missing，宁可要求重述不猜指代。

**6. 上下文怎么管理？预算怎么算？**
一轮 = 1 问 1 答 = 2 条消息，deque(maxlen=10) 自动丢弃。超 maxlen 截断置 missing，追问指代会走"请重述"文案。会话级锁粒度 = session_id，2s 超时降级为无历史并明确告知。单 worker 边界：WEB_CONCURRENCY>1 整体降级为无历史模式，宁可明确降级不提供"看起来有上下文实际片段化"的历史；不引入 Redis，会话读写集中在 session.py 一个模块，替换成本低。子 Agent 不传会话历史，本身就是上下文隔离。注意：预算目前按时间（45s 总 deadline + 逐环节），不做 token 级预算——这是已知边界。

**7. 子 Agent 委派怎么设计？"受控"体现在哪？**
体现在四点：①是否委派由路由表写死，不由模型决定；②启动预算检查，剩余不足 8s 不启动，防"假动作"；③上下文隔离——子 Agent 只拿到 question + deadline，不继承父状态，避免检索循环污染会话；④结果经 SubagentResult 契约结构化返回，父侧是唯一解释点（status → 终止原因 + 固定文案），子 Agent 的工具记录和 trace 重排 seq 并入父状态保证追踪连续。子 Agent 内部仍有完整的降级语义（连续失败阈值、回边守卫、预算守卫）。

**8. 超时和预算体系怎么设计的？（踩坑点）**
两个实现陷阱是踩过/预演过的：①`future.result(timeout)` 只让调用方放弃等待，不终止底层线程；②`with ThreadPoolExecutor()` 退出时 `shutdown(wait=True)` 会继续等到任务结束——超时完全失效。所以 LLM 超时全部走 httpx 原生 timeout（真正生效），检索实测 p95=11.2ms 后明确不引入线程池。预算规则：环节预算 = min(配置, 剩余)，<3s 不启动该环节直接走降级分支；这样 45s 整体上限是硬上限而非"检查了拦不住"。每个环节超时值必须等于分配到的预算。

**9. 怎么排查检索错误和幻觉？评估体系是什么？**
三层：①trace 归因——每次判定留 reason（如 stage3_not_answerable、stage2_quote_not_found），定位是哪一段拦的；②固定测试集——72 题分领域覆盖测试，逐题落盘 top-10 文档、距离、chunk 摘录、回答摘录，分类口径 A~S（覆盖充分/判定拒答/检索失败/知识缺失/路由走/安全拦截），拒答题必须逐题归因不许糊过去；③人工核验——FR-01 对 8 个样本 104 句医学陈述逐句对照来源，AI 辅助核验 100% 有出处（待人工抽查背书）。72 题驱动了三轮真实改进：判定层口径修复（50%→79.2%）、意图边界修复（路由走 8→1 题）、资料补全（→81.9%）。

**10. 性能优化具体做了什么？量化效果是？**
最大的一个是 embedding/vectorstore 客户端单例化：原实现每次检索新建客户端、重新加载模型（warm-up 的对象被丢弃），检索环节实测 9.7~15.6s，预算 5s 超支 2~3 倍，G-3 门禁不过。改为双重检查锁单例后检索 14ms，34 条真实请求最大耗时从超 45s 降到最大 6.6s。其他：章节切分让答案段进 top-k（T-13-1 从拒答转 completed）；temperature=0 + 判定口径修正消除"同一证据判定掷硬币"；引文校验失败做有界重试（只修格式不翻结论）。量化指标只引用测试集口径，不说"系统正确率"。

（备选追问：登录安全——scrypt(N=32768) 哈希、库里只存 token 的 SHA-256 摘要、双层限流 username+IP 5 次锁 15 分钟、哑哈希对齐耗时防计时枚举、资源级 403 不区分"不存在/不属于你"防枚举。）
